# Visual and interaction craft

Use after the task structure is understood, before visual implementation.
Craft makes a coherent experience legible and distinctive; it does not rescue
a structure that is confusing in monochrome.

## Compose around the subject

Identify the real object of attention: a decision, comparison, process,
collection, narrative or action. Make that object lead rather than a generic
hero. Preserve an existing identity; for a new one, explain the intended
character in terms of the audience and usage scene.

Use hierarchy, alignment and grouping deliberately. Vary composition when the
content changes function, not by alternating arbitrary section backgrounds.
Consistency within a project is valuable; identical topology across unrelated
projects is not.

No universal ban on serif, system fonts, cards, gradients, symmetry or color.
No compulsory "signature interaction", ornamental KPI, decorative status dot,
oversized hero or cinematic sequence. Familiar controls can be the right choice.

## Typography and space

Choose a readable body face, a useful scale and meaningful emphasis. One family
can suffice. Use tabular figures for numeric comparison when appropriate.
Line measure and spacing depend on language, type and task; a prose guideline
does not cap a data table's width.

Space should reveal relationships. A large empty margin does not automatically
reduce cognitive load, and tight spacing does not automatically make an expert
table unusable. Avoid equal visual weight for every sentence and control.
Do not reduce text size to force content into one viewport.

## Visual explanations

| Question | Candidate representation | Check |
|---|---|---|
| How do parts relate? | Diagram with named roles and relationships | Are edges meaningful and the reading order understandable? |
| Which option differs? | Aligned comparison matrix | Can the reader compare without memorizing another view? |
| What changed over time? | Appropriate chart plus text/data alternative | Are units, period, scale and uncertainty explicit? |
| What can I do next? | Real controls with clear action labels | Does activation produce the promised result? |
| What is this object? | Relevant image, preview or concise description | Is it informative rather than decorative evidence? |

Do not turn every idea into boxes and arrows. A diagram of responsibilities
must not imply that a workflow, integration or control has actually been
implemented. Distinguish illustrative material from observed operation.

## Icons

Use a consistent family and stable meanings for destinations, actions, objects
and state. Pair ambiguous icons with visible labels. Icon-only controls need
accessible names and discoverable behavior, not hover-only explanations.
Hide purely redundant decoration from the accessibility tree.

Good: an evidence icon beside "Sources", a filter icon beside active constraints,
or distinct roles inside a process diagram.

Bad: the same arrow appended everywhere, unlabeled navigation symbols, or a
decorative icon on every paragraph. There is no icon quota.

## Motion

Assign each animation a purpose: acknowledge input, show a state change,
preserve continuity, or help track a data transformation. Match timing to
distance and complexity rather than applying one magic duration everywhere.

Allow interruption and continued input. Keep content visible and usable without
entrance animations. Support reduced motion without replacing a manageable
multi-view experience with an obligatory all-open document.

Good: a detail transition that makes its relationship to the selected item
clear, and immediate equivalent behavior with reduced motion.

Bad: a fade on the hero counted as complete interaction design; scroll hijacking;
waiting for each paragraph to reveal; decorative loops competing with reading.

## States, color and evidence

Use color roles, not color alone. Distinguish selected, active, disabled, loading,
empty, error and success where those states actually exist. Preserve input on
recoverable errors and explain the next action.

Model independent states separately. An available application is not the same
as accepted evidence; a draft is not an approved decision. Put the decisive
limit next to the related action, then link to the full explanation.

Use actual brand assets only with appropriate rights. No invented logos,
testimonials, customer names or plausible-looking metrics. Missing imagery does
not prevent a good typographic, diagrammatic or data-driven result.
