## Local checks

The source provides a targeted contract suite:

```bash
python3 -m unittest scripts.tests.test_web_experience_design_contract
python3 scripts/validate-skills.py
python3 scripts/build-plugins.py --check
python3 scripts/build-site.py --out docs/ --validate
```

Passing these commands is not a substitute for the output acceptance below.
PR-specific results belong in the PR evidence. The merged source provenance
above is not browser/output acceptance or native runtime validation.

### Observed local results, 2026-09-21

- New skill contract suite: **13 tests passed**.
- Targeted catalog regression set: **44 tests passed**, including those 13,
  fresh-site publication, existing candidate status and catalog inventory.
- Catalog T0 and plugin structure: **passed**; 40 skills and 35 upstream pins.
- Generated site: **49 HTML files, zero broken root-relative links**.
- Full unittest discovery: **1350 cases**, no import failures after restoring
  the CI-declared APIM test dependency in an isolated environment. This is a
  discovery count, not a claim that all 1350 cases were executed.

The generated candidate page and validation link were inspected locally.
Desktop rendered the expected status. At 390 CSS px, the shared catalog
navigation overflowed to 534 px; the same overflow was reproduced on an
unchanged existing skill page. The shared template was not changed by this
addition. The preview also requested an absent favicon. These pre-existing
catalog presentation issues are not a successful mobile-quality result and
are separate from testing interfaces generated by the new skill.

## Required output acceptance

Run the skill's
[three scenarios](../../skills/web-experience-design/tests/scenarios.md)
in isolated scope: executive report, comparison/tool and a different
informational identity. Include a user-selected real baseline where available.
For each run record the skill revision, runtime, tool availability, approved
structure, actual artifacts, task outcomes, viewport/keyboard conditions,
applicable print/offline evidence and owner decision.

No score assigned by the generating agent can close these gates. No confidential
material goes to an external design service. Any optional remote generation
requires separate approval of the payload, destination, terms and bounded cost.

Until that evidence is accepted: keep release and global promotion pending,
do not install it globally as a default, and do not describe it as
production-proven. These gates do not hide the already merged catalog source.
